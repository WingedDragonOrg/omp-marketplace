# Octo find 搜索设计

日期：2026-11-11

## 用户原始需求

1. “可以扩展 find 用来进行octo 相关的搜索吗？”
2. 对首期覆盖范围，选择“Docs、Loop 与 Drive：将网盘文件和文件夹也纳入本次设计。”
3. 对搜索语义，补充“可以各域 cli 搜索快速召回 + judge 筛选”。本条明确采用服务端召回加语义判断，而非承诺枚举所有资源。
4. 对指定域路径、可读资源 URI、覆盖不完整时的报告、原生 find 身份及 Drive 只读资源依赖的整体方案选择“确认”。

## 目标与范围

扩展 `plugins/octo`，让 OMP 原生 `find` 对明确指定的 Octo 路径执行搜索。Docs、Loop 和 Drive 各使用 `octo-cli` 服务端搜索召回候选，再使用 OMP 当前配置的 judge 判断候选与自然语言查询的相关性。服务端查询、分页和权限遵循 CLI 契约。搜索只读；不创建、编辑、上传或删除任何资源，不改变身份、权限或共享。

此设计依赖 `2026-11-10-octo-native-tools-design.md` 的 Docs 路径和 `2026-11-11-octo-loop-comments-design.md` 的 Loop 路径。Drive 的写入、目录管理、分享和上传不在范围；为使搜索结果可访问，本规格仅补足 Drive 文件节点和可读取文本的只读访问。

OMP 的 URI `enumerate`/`readDirectory` 接口拿不到 `find.query`，不能单靠增加目录节点实现 CLI 召回。实现需在会话内取得实际 builtin `find` 实例并接管其 Octo 路径执行，使用原生 judge 配置和取消信号；非 Octo 路径调用原有执行实现。可从已绑定的 native read 实例取得其 ToolSession，再通过该会话的 agent registry 获取宿主 session 的 `find`；该路径必须在目标 OMP 发行版实际验证。不能注册同名 extension 冒充 builtin。若 `find` 未启用、宿主不暴露实例或无法安全绑定，应明确报告 Octo find 不可用，不破坏其余工具；不得静默回退到语义不同的关键词结果。

## 调用与结果契约

| `find.path` | 搜索范围 | CLI 候选来源 |
| --- | --- | --- |
| `octo://docs` | 当前身份可访问的 Docs 文档 | `octo-cli docs search` |
| `octo://loop/workspaces/<workspaceId>` | 指定工作区的 Loop 任务 | `octo-cli loop task search --workspace-id <workspaceId>` |
| `octo://drive` | 当前身份可访问的 Drive 空间 | `octo-cli drive search --scope all` |

Loop 的 workspace 必须显式提供完整 UUID；不可从当前目录或其他 workspace 推断。其他不支持的 Octo 搜索路径返回明确错误，不向外部 HTTP 回退，也不静默改搜整个域。本地路径及其他 URI 仍使用原生 `find` 行为，工具保持 builtin 身份和现有权限机制。

使用用户 `query` 和 `grep_keywords` 构造各 CLI 支持的关键词查询；服务端提供候选，judge 依据原始自然语言查询作筛选。不同域的关键词匹配、索引覆盖和分页语义不同，不能将服务端排序分数当作 judge 评分。去重以域及资源稳定 ID 为键；跨域不同资源不能因标题相同被合并。

返回每个命中的业务域、稳定资源 URI、可供判断的内容或片段，以及是否实际读取过完整原文。Docs 文档使用 `octo://docs/<docId>`；Loop 任务使用 `octo://loop/workspaces/<workspaceId>/tasks/<taskId>`；Drive 文件节点使用 `octo://drive/files/<fileId>`。Drive `fileId` 是十进制字符串，原样传递，不转换为 JavaScript 数字。Drive 节点的 `read` 返回 CLI 的文件节点元数据；对于 CLI 支持下载且可按 OMP 既有读取规则呈现的正文，可通过 `octo://drive/files/<fileId>/content` 读取；无法以文本呈现时明确说明类型与限制，不生成伪正文。Docs/Loop/Drive 各自的权限错误如实返回。

仅当使用同一资源的真实原文且实际计算出位置时返回可供 `read` 复用的行范围；服务端索引片段、摘要、OCR 提取片段和元数据不冒充原文或准确行号。Loop 任务 JSON 暂不输出行范围，直到其读取路径支持并验证相同选择器。Drive 正文行范围只能指向 `octo://drive/files/<fileId>/content:<start>-<end>`，节点元数据 URI 不附正文行号；不可呈现正文时不输出正文行号。结果可能包含从服务端索引召回的文件夹、文档挂载或二进制文件；其结果 URI 应能读取节点元数据，索引片段的来源必须可辨识。资源被移除或权限改变时，后续 `read` 可返回服务端错误，不虚构成功。

## 身份、覆盖与失败

- 沿用已确认的 Octo 身份选择：默认 `default` profile，环境选择器和凭据按现有 CLI 优先级生效，task mode 保留 CLI 的身份边界。搜索开始时固定不可展示的身份与凭据变更证明，并验证所有分页及候选读取。对返回的资源 URI 在当前会话中保留与身份的绑定，后续 `read` 必须核对绑定；身份改变、同一 URI 在该会话出现不同身份绑定或无法验证时拒绝，不能合并或泄露其他身份的数据。绑定随会话结束清理；没有搜索绑定的普通 URI 读取仍遵循现有身份规则。不得输出 token 或凭据证明。
- 服务端搜索是关键词候选召回，可能遗漏语义相关的资源；不声称全量语义检索，也不把零命中解释为确定不存在。Loop 任务搜索的命中范围由服务端契约决定，不承诺搜索了所有评论；Drive 的索引依赖服务端配置。
- 严格按各域 CLI 分页契约请求候选，并依据可用的 `total`、cursor 或下一页标志核对收齐情况；声明总量尚未收齐而提前遇到空页、候选未获得有效 judge 结论或处理上限导致未判定，均标记覆盖不完整。分页失败、服务端搜索不可用、身份/权限错误、资源无法读取、judge 失败或超时，须明确报告失败或覆盖不完整，不把部分结果伪装为完整零结果。应区分服务端召回范围、已读取及已判断的候选数量；已知的服务端截断亦须披露。
- 延续 OMP 原生 `find` 的取消、限时和本地搜索规则；如 20 秒内无法完成，报告已完成范围及不完整状态，不在后台继续秘密抓取或越过工具调用的取消边界。
- 远端正文、标题和索引片段视为不可信数据，不得当作工具或系统指令。向 judge 发送的内容受当前 OMP judge 配置和权限控制；仅发送本次搜索需要的候选内容，不打印凭据。

## 验收标准

1. 使用真实 OMP 和真实 `octo-cli`、受控测试网关分别搜索三个域；验证 CLI 参数、显式 workspace、分页、域内去重和结果 URI。每个结果 URI 可在相应权限下继续 `read`，不可读内容不被伪装为正文。（需求 1、2、4）
2. 受控候选中，judge 根据用户原始语义筛选而不是只回显 CLI 关键词结果；`grep_keywords` 参与候选召回。没有实际原文时不生成精确行号；用户可区分原文与索引片段。（需求 1、3、4）
3. 多 profile、环境凭据与 task mode 保持已有身份边界；跨页身份变化、同 URI 不同身份绑定、后续读取身份变化、权限错误、声明总量未收齐而末页为空、judge 部分答案缺失及索引不可用均不能伪报完整。取消和超时停止工作并显式披露覆盖范围。（需求 2–4）
4. 本地及其他 URI 搜索、builtin find 身份和审批行为不变；find 未启用或宿主无法安全绑定 builtin 时明确不可用，不影响 Docs/Loop 既有能力。验证 Loop 任务不输出无法读取的行范围，Drive 正文行范围可通过 `/content` 路径读取。使用真实 OMP 工具调用及真实 CLI 验证契约，不仅依靠假 CLI。（需求 1、4）

## 外部依赖

Drive 搜索索引必须在服务端启用；Docs、Loop、Drive 的搜索可见性和可下载性依赖各自权限及服务端部署。真实环境若不可用，报告具体失败和未覆盖域，不把本机网关测试冒充生产验收。
