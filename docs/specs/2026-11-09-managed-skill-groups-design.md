## 目标和范围

扩展 `plugins/auto-learn-scope/`，使全局 managed Skill 通过任意层级的组索引逐级展开，最终读取子 Skill 正文。初始模型清单只展示顶层组的名称和简短 description；读取任一组后获得其直接子组和直属 Skill 的名称、description 和读取路径。

组和子 Skill 存放在 OMP 原有 managed-skills 目录。用户负责移动已有 Skill；本设计不执行迁移、不改写旧引用、不自动整理或合并 Skill。现存平铺 Skill 继续按原有发现机制工作。原有 project scope 不改布局或调用语义。

## 当前事实与约束

- `auto-learn-scope` 已同名注册 `learn` 和 `manage_skill`；global Skill 由插件写入，project Skill 由插件按原有布局写入，memory 委托 native `learn`。
- 当前 OMP 18.18.3 源码中的 managed provider 只扫描根目录下一层的 `SKILL.md`；`skill://<组>/<相对路径>` 可读取组内文件。两者是版本相关约束，不承诺其他版本相同。
- 隔离探针使用 OMP 18.18.3：extension factory 创建顶层组 `SKILL.md` 后，`session_start` 的 active skills 包含该组而不包含子 Skill；独立 `omp read` 成功读取 `skill://probe-group/probe-child/SKILL.md`。探针未验证所有插件并发、符号链接或现有交叉引用。
- 部分现有 managed Skill 是由外部工具管理的符号链接；目录扫描和读取不得修改链接目标或链接管理清单。旧 `skill://子名称` 在子 Skill 移入组后不保证可解析，用户手动迁移时负责相关引用。
- 本设计改变已有 auto-learn-scope 规格的 global Skill 写入契约：group 必填并支持多段路径，插件写组内 Skill；原有单段组、project scope 和 memory 委托契约不变。

## 布局和索引

```text
managed-skills/
  engineering/
    SKILL.md
    database/
      SKILL.md
      postgresql/
        SKILL.md
        postgresql-readonly-space-audit/
          SKILL.md
```

- 每级组目录的 `SKILL.md` 是带固定工具标记的生成索引，frontmatter 的 `name` 为该级目录名，`description` 为组摘要。正文列出直接子组和直属 Skill，分别标明类型，按名称稳定排序，每项包含名称、完整 description 和从顶层组出发的 `skill://<顶层组>/<相对路径>/SKILL.md` 路径。父组可以同时包含子组和直属 Skill。
- 子 Skill frontmatter 是其名称和 description 的唯一来源；正文及其他文件保持不变。子组条目使用子组生成索引的 name 和 description。索引正文保留直接条目的完整 description；每级组的 description 由模型根据该组全部直接条目生成，不超过 200 个 Unicode 字符，覆盖不同主题、触发场景和明确的排除条件。工具负责维护，不由 agent 手工编写；生成不得依赖当前目录特定的组名、Skill 名或主题规则。
- `group` 是 `/` 分隔的非空路径，每段和子 Skill 名称均按原有命名规范校验；拒绝绝对路径、空段、`.`、`..`、反斜杠和路径穿越。单段组保留原有语义。创建缺失组时自顶向下创建目录并生成各级索引。
- 各级索引以标记区分组与普通 Skill：标记必须是 frontmatter 结束分隔线后的空行之后的精确整行 `<!-- auto-learn-scope managed skill group index -->`，与现有生成索引位置一致。其他位置出现标记不能作为组身份依据；标记缺失、损坏或位置不符的 `SKILL.md` 是用户数据，不转换、不覆盖，尝试在其下创建组时报冲突。无 `SKILL.md` 且包含可识别的子组或直接子 Skill 的目录，自底向上识别为新组；空目录不自动识别为组。带标记的空组仍是组。用户手工移动已有 Skill，不自动迁移或改写引用。
- 每组按直属 Skill frontmatter 建立名称到实际目录的映射；更新和删除使用映射而非假定目录同名。直属 Skill 名称或目录与直接子组发生冲突，或组内出现重复名称时，停止并报告冲突，不修改成员；不同组可使用相同名称。
- managed 根目录可为符号链接，启动时固定解析目标。任何层级的组目录或组索引文件为符号链接时，不创建或替换该组索引并报告冲突；直属 Skill 目录符号链接仅用于读取和索引，不通过自动写入修改其目标。安全边界以解析后的 managed 根目录为准。
- 索引重建只修改组 `SKILL.md`，内容不变时不写入；原子替换索引，不改变成员或其他文件。工具写入、启动扫描和读取前重建统一按顶层组跨进程互斥，锁内重新扫描相关子树并自底向上更新受影响索引；不同顶层组可并行。确定性重建保留上次成功的模型摘要，更新正文和 revision；缺少摘要的新组先按现有确定性方式生成可发现的初始 description，并标记摘要未生成，不伪报模型摘要已完成。锁内失败必须可见并释放协调资源。手工或外部修改不受此锁约束，下一次读取或刷新重建，不承诺并发手工修改在当前次索引中立即可见。

## 发现与刷新

- 扩展初始化阶段在 OMP 初次发现前，自底向上扫描并生成或更新各级组索引；OMP 顶层清单只发现顶层组，不把子组或成员作为独立顶层 Skill。不得依赖 `session_start` 后的自动重新发现。
- 读取 `skill://<顶层组>`、其索引的等价路径或 `skill://<顶层组>/<相对路径>/SKILL.md` 前，根据宿主实际解析目标识别组路径，在顶层组锁内重新扫描并刷新相关子树及其祖先索引；读取直属成员时同样先刷新所属组及祖先。裸顶层 URI 也须执行索引条目遮蔽检查。不得重写普通 Skill；无法重建时报告失败而不是返回旧索引。不能执行组内文件内容。
- OMP 对 `skill://<顶层组>/<首段>/...` 的同名命名空间 Skill 优先于顶层组相对路径。初始索引可在宿主发现前写入；在向模型返回组索引前，必须依据当前 active skills 检查其条目的实际解析目标。受遮蔽时报告冲突，不返回含误导性链接的索引；不拦截用户直接读取合法命名空间 Skill。顶层同名 authored Skill 仍按原有冲突规则处理。
- `/refresh-managed-skills` 扫描目录并手动全面重建所有组的模型摘要，不调用 `/reload-plugins`。已发现顶层组内新增、移动或修改的子组和成员在下次读取相关组或刷新后反映；当前会话顶层 Skill 清单是快照，更新的顶层 description 和运行中新增的顶层组在新会话发现时生效，不承诺即时修改当前快照。

## 模型摘要与并发

- 仅 global `learn` / `manage_skill` 成功**新增**子 Skill 时自动请求摘要更新：更新其所属组和各祖先组；连续新增可合并。更新成员内容、删除成员或成员数量不变的替换只维护确定性索引和 revision，不自动调用模型。手工目录变更通过读取维护索引；用户执行 `/refresh-managed-skills` 时扫描并对全部组自底向上重新生成摘要，包括内容更新、删除和手工迁移后的组。
- 自动与手动生成均按受影响树自底向上进行：父组对本轮受影响的直接子组使用本轮已成功提交的摘要；不受影响的子组使用其现有 description，保留其未生成或过期状态。受影响子组本轮失败或冲突时，依赖它的父组本轮标记阻塞并报告，不以旧子组摘要声称完成。新增触发的待处理状态在对应索引提交时持久化，随后才能报告 Skill/索引已提交且摘要待生成；手动发现的无摘要组不因此自动调用模型。
- 为覆盖成员已提交但索引尚未提交时进程退出的窗口，新增操作在成员提交前持久化可恢复的新增意图，记录目标和预期成员内容标识；意图、完成和取消状态具有持久化操作标识及同一顶层组内的顺序。同组后续写入在锁内先协调未决意图，恢复按该顺序幂等处理，不重放已完成或取消的工作。恢复时核对提交结果，仅对确认已提交的新增恢复对应组与祖先组的自动摘要任务。未提交或状态无法确认时报告实际状态，不凭意图虚构新增成功。索引完成与新增待处理状态的持久化必须能恢复至一致状态。
- 对同一组的后续内容更新或删除，使基于此前成员快照的自动任务失效并标记待手动刷新；之后又有新的 Skill 新增时，才产生新的自动任务。该顺序规则同样适用于任务尚未启动、正在生成或进程重启后的恢复。
- 摘要调用只提供组名以及全部直接成员、直接子组的 name 和 description，不发送 Skill 正文。使用宿主配置的小型生成模型；模型或其 provider 不可用、输出为空或超过长度限制时明确报告失败，保留上次成功摘要并标记待更新。远程模型会接收这些元数据。单次成员操作在确定性索引提交后返回，不等待后台模型生成；结果区分 Skill/索引已提交与摘要待生成，不把待生成描述为已完成。
- 每个工具管理的组索引 frontmatter 包含 CAS `revision`。每次实际修改该索引的正文、摘要或摘要状态都原子更新 revision；没有实际变化时不写入。revision 具有跨删除重建的唯一性，不能因重建重用旧值。历史带标记索引缺少 revision 时由工具在首次实际维护时添加，原有普通 Skill 不修改。revision 是并发控制标记，不是格式版本。
- 每个组的待处理工作有持久化递增代次，连续新增即使合并也推进代次。生成任务在顶层组锁内读取 revision、所覆盖的工作代次、受影响直接子组的代次、状态和 revision，以及完整直接条目快照；保存相关成员 `SKILL.md` 全文的本地内容指纹，但不发送正文或指纹给模型。释放锁后调用模型；恢复、启动生成及提交前重新扫描并核对本地内容指纹，发现既有成员内容更新则取消旧自动任务并标记待手动刷新。提交时重新取得锁，重新扫描并比较 revision、工作代次、受影响子组依赖及成员快照，一致才基于**最新索引**原子写入摘要及新 revision，只完成所覆盖的代次，新代次继续待处理。任一不一致则丢弃生成结果；新增加入的待处理请求继续生成，若仅有内容更新或删除导致冲突则标记待手动刷新，不由此自动调用模型。两个任务基于相同 revision 完成时，先提交者更新 revision，后提交者不能覆盖。
- 外部文件操作不受插件锁和 revision 约束；提交前扫描可以发现已发生的外部变更，但不承诺阻止外部程序在检查与写入之间并发修改。模型生成失败、进程退出或 CAS 冲突均不得回滚已提交成员；可见状态区分由新增触发且尚未完成的工作与仅待手动刷新的过期摘要。新增触发的未完成工作在下一次会话可恢复；内容更新或删除本身不触发自动模型调用。手动命令等待本次全面生成完成并逐组报告成功、失败或冲突。
- Decisions 模型只作为验收中的可选对照：比较直接生成、决策模型选取短语和生成后决策校验的质量、耗时与成本；没有实测净收益前不引入运行时必经步骤。评测使用独立任务与近似负例，分别测量组命中、组内成员选择和误触发，不以成员词语出现率代替召回。

## `learn` 与 `manage_skill` 契约

- `learn.skill.group`、`manage_skill.group` 是 global Skill 操作必填的合法组路径；省略或不合法时明确报错，不回退到平铺路径。仅 memory 的 `learn` 不要求 group。project scope 的旧参数和行为保持不变。
- 对 global `learn`，先用去掉 `skill`、`scope` 和插件专用字段的参数委托 native `learn` 保存 memory；memory 失败不写 Skill。memory 成功后创建或更新组内 Skill 并更新组索引。后续失败时报告 memory 已成功、Skill 与索引各自的结果和路径，不伪报整体成功。
- 对 global `manage_skill`，插件在目标组执行 create/update/delete 并自底向上更新目标组及祖先索引，保留原有动作的存在性语义、启用条件、审批等级和清晰错误。缺失组路径逐级创建；与普通 Skill 或受保护链接冲突时停止。删除最后一个成员后组索引仍可存在，供后续复用。
- 不改变 native memory backend、auto-learn controller、触发阈值和 native hidden capture；更新工具 schema、描述及引导，使后台 capture 能提供 group。必须用真实 OMP 验证 hidden capture 实际调用该 wrapper，不能只以注册成功为证。
- 结果按提交点区分：确认未写入、已写入但索引待重建、以及无法确认是否已写入；不得把提交后的检查失败报告为肯定未写入。涉及 global Skill 的成功和失败结果均包含 Skill 状态和路径，以及目标组到顶层组的逐索引结果列表；global `learn` 还包含 memory 状态。纯 memory 的 `learn` 保持原有返回。每项索引结果包含完整组路径、索引路径、提交状态 `written`、`not-written` 或 `unknown`，以及是否需要重建；未写入项进一步标明写入失败或尚未尝试。失败或状态不明时，后续刷新或读取重新扫描并重建；不得静默回滚 memory。

## 验收标准

1. 手工建立一个没有组 `SKILL.md` 的组并放入两个子 Skill，启动隔离 OMP 会话后组自动出现；初始清单只包含组条目，不包含子 Skill 条目。读取组后能看到两者完整名称、description 和路径，再能读取对应正文。（需求 1、2、6、7）
2. 手动修改、新增、移走子 Skill 后，下一次读取组反映变化；运行中新增顶层组在新会话发现，刷新不重载当前会话；已有平铺 Skill 的内容不变。（需求 2、6、7、16）
3. 两个工具按显式 group 在现有组内写入或创建新组，缺失 group 明确报错；纯 memory 与 project 路径保持原契约；创建、更新、删除和索引内容一致。（需求 3–5、7）
4. 使用真实 OMP hidden capture 验证 wrapper、group 参数和 memory 委托；模拟 memory、Skill 和索引失败，检查可见部分成功结果与后续重建。（需求 3–5）
5. 使用顶层链接、索引文件链接、符号链接成员和同名冲突检验不改变链接目标、不覆盖普通顶层 Skill；跨进程并发修改同组成员后索引包含全部已成功写入成员。测试名称与目录不一致及重复名称的处理，并在提交前后注入故障验证未写入、已写入和状态不明结果。（需求 4、6、7）
6. 比较迁移前后实际 provider 请求中的 managed Skill 清单大小，并用代表性任务检查组 description 能引导读取正确组；记录测量和未命中情况，不把目录数减少当作召回质量证明。（需求 1、2）
7. 三层组内同时包含直属 Skill 和子组：真实 OMP 初始清单只出现顶层组，逐级读取各索引能到达正确成员正文；每级索引只列直接条目，完整 description 可见。（需求 2、8–10）
8. 两个工具使用多段 group 创建、更新、删除；缺失祖先自动创建且各级索引更新。手动新增、修改或移走深层成员后读取可见更新；单段 group、纯 memory 和 project scope 保持原有行为。（需求 4、6、8–10）
9. 在不同进程同时修改同一顶层组的不同分支，最终每级索引反映所有已成功写入的成员；对成员写入和各级索引注入失败，检查各提交状态、路径及后续重建。不同顶层组可并行。（需求 8–10）
10. 以真实 OMP 验证全新会话首次启动即存在的命名空间遮蔽在索引返回前被明确报告，直接读取同名命名空间 Skill 仍可用；验证普通 Skill 子目录、正文包含组标记、各级符号链接、重复名称、路径穿越和组路径与直属成员冲突均不覆盖用户文件。（需求 6、8–10）
11. 使用通用成员数据和独立正例、近似负例验证模型摘要与渐进加载的组命中、成员选择、误触发及上下文开销；记录未命中及不同模型方案的耗时和成本，不声称保证召回。（需求 11–15）
12. 新增成员自动触发所属组和祖先组摘要更新，连续新增可合并；内容更新、删除和数量不变的替换不触发模型调用，但索引与 revision 正确更新。手动 `/refresh-managed-skills` 重新生成所有组摘要，并报告每组结果；两种路径均不调用 `/reload-plugins`。（需求 15–17）
13. 使用真实 OMP 验证摘要更新后经裸 `skill://<顶层组>` 读取会先重建并检查遮蔽，已发现组的正文可读、当前会话顶层清单保持快照，新会话发现最新顶层摘要和新组；验证远程模型只收到名称与 description，不收到成员正文。（需求 12、15–17）
14. 跨进程交错模型生成与新增、内容更新、删除及另一生成提交，包括子组新代次先于其 description 更新的情况，验证旧 revision 不覆盖新索引、不清除新代次；在新增意图、成员提交、索引和待处理状态提交之间分别终止进程，并让另一进程继续更新或新增，验证有序幂等恢复及不虚报新增。模拟只改成员正文的外部变化、模型失败和子组失败，验证旧自动任务失效、保留上次摘要、受影响父组阻塞且未受影响子组不被自动重生成；仅新增产生的未完成工作可在新会话恢复，手动刷新可修复过期摘要。（需求 17–20）
